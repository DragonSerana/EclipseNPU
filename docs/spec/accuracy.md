# 数值精度合同（Accuracy）

## v0.1：fp16 误差模型

MATMUL 语义：fp16 输入 → fp32 块内累加 → fp16 写回。
K 分块接力（accumulate=1）时，每块边界多一次 fp16 舍入。
v0.2 由 fp32 ACC 区消除，v0.1 接受并量化。本文档给对拍容差 1e-2 一个出处。

### 误差来源

1. 输入量化：A/B 存 fp16 舍入一次，≤ 2^-11（RNE，0.5 ulp）。
2. 块内 fp32 累加：fp16×fp16 的乘积在 fp32 中精确（11×11 < 24 位），
   累加每步舍入 ~2^-24，K ≤ 1024 累积 ~1e-6，相对写回舍入可忽略。
3. 写回舍入：块内和 fp32→fp16，一次，≤ 2^-11。
   我们的 SRAM 小，每块结果必须落回 fp16 腾地方；PyTorch 的 fp32
   累加器不落地，一直算到最后才舍入——这就是跨块误差的根源。
4. 跨块接力：每块一次写回，误差独立无偏，按 √N 随机游走累积。

### 与 golden 的合理误差

- 单块 ~2^-11 ≈ 5e-4；分 N 块 ≈ √N × 5e-4（K=128 分 4 块 ≈ 1e-3）。
- 容差 1e-2 覆盖 5 倍以上余量。
- 即使不分块，与 PyTorch 也逐位不齐（见下），容差不能拍死。

### 为什么浮点对不齐：结合律不成立

fp32 加法每步都舍入到 23 位尾数。IEEE754 加法满足交换律
（a+b == b+a，舍入对称），但不满足结合律：(a+b)+c 与 a+(b+c)
中间结果的舍入位置不同，结果可能不同。cmodel 按 m,n,k 顺序逐项加，
cublas 用分块/树形归约，求和顺序不同 → 末位 ~1e-7 量级差异，
比 fp16 写回小三个数量级，可忽略但永远存在。

### 实测验证

| 分块数 | 理论 √N×5e-4 | 实测 max rel err（vs torch fp16，默认） | 实测 max rel err（vs fp64，附录） |
|---|---|---|---|
| 1 | 5e-4 | ≈6.1e-4 | 3.0e-4 |
| 2 | 7e-4 | ≈6.1e-4 | 3.9e-4 |
| 4 | 1e-3 | ≈6.1e-4 | 5.8e-4 |
| 8 | 1.4e-3 | ≈6.1e-4 | 8.4e-4 |

默认对拍口径是 torch fp16（`matmul_check.py` 的 golden 路径）。
torch fp16 各档均约 6.1e-4——最大误差元素固定在一个近相消元素上
（golden 接近 0、中间项大），由 fp32 求和顺序主导，对分块数不敏感；
fp64 列作为附录，用于观察跨块舍入的实证，实测按 √N 增长但低于理论，
符合"RNE 无偏、随机游走"的预期（理论取 0.5 ulp 上界）。

（对拍目标误差，PyTorch 写回 fp16 也有自己的舍入）。
