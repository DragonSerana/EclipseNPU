## 0. 先用计数器搞清"组合 vs 时序"（30 分钟，做完再往下）

`rtl/pip/counter.sv` + `rtl/tb/pip/tb_counter.cpp` 已经能跑、GTKWave 能看到波形了。开始 R1 之前先做这三个实验，否则 valid/ready 会写得很玄。

> 波形里把时间换成拍号：`拍号 = 时间 ÷ 2`，余数 0 是 clk=0 那一刻，余数 1 是 clk=1（上升沿之后）那一刻。GTKWave 显示成 ps 只是 Verilator 的默认时间单位（1ps/1ps），跟真实时间无关，别去读它。

**实验 1：加一个组合输出**

在 `counter.sv` 的端口里加上 `output logic [7:0] cnt_next`，模块体里加一行：

```systemverilog
assign cnt_next = cnt + 8'd1;
```

重新 lint + 构建 + 跑，在 GTKWave 里把 `cnt` 和 `cnt_next` 放在一起看。

- 观察：这两个信号是不是在同一时刻变化？是同时变化
- 回答：`cnt` 从 3 变 4 的那一刻，`cnt_next` 从 4 变 5。

**实验 2：把时序逻辑改成用那个组合值**

把 `always_ff` 里的 `cnt <= cnt + 8'd1;` 换成 `cnt <= cnt_next;`，重新跑。

- 回答：波形变了吗？为什么？ 没有变。cnt_next是一个导线，本质就是立即生效的cnt+1。cnt <= cnt + 8'd1和cnt <= cnt_next因为都在寄存器中，所以逻辑上一样，都是clk到来后加一

**实验 3：改输入到底哪一拍生效**

把 TB 里 `if (t == 2) top->rst_n = 1;` 这一行，挪到本次循环 `top->clk = 1; top->eval();` 的**前面**，再跑一次，看 `cnt` 第一次变成 1 是第几拍。两次对比。

- 回答：在 TB 里改一个输入，是在"当前这一拍"生效，还是"下一拍"生效？开始是7ps生效，该后变成5ps生效

做完这三个再回头看 §2 的三条约束，就能明白为什么 `m_valid` 必须是寄存器、而 `s_ready` 可以是组合。

## 1. 端口

`s_` = slave 侧，也就是**上游那一侧**，模块在这里**收**数据；`m_` = master 侧，**下游那一侧**，模块在这里**发**数据。这两个前缀来自 AXI 的写法（`s_axis_*` / `m_axis_*`），看别人的代码和波形时通用。

每个接口三根线：`valid`（我有数据）、`ready`（我能收）、`data`（数据本体）。方向规则是固定的，不由模块的视角决定：

- `valid` 和 `data` 同向，**由发送方驱动**；
- `ready` 反向，**由接收方驱动**；
- 一次传输成立 = 在同一个时钟沿上采到 `valid && ready` 同时为 1。

所以本模块对上游是接收方（`s_valid` / `s_data` 是输入，`s_ready` 是输出），对下游是发送方（`m_valid` / `m_data` 是输出，`m_ready` 是输入）。唯一容易记混的地方：**两个 `ready` 的方向都和同侧的 `valid` 相反**。

```
        上游  ──→ s_valid   ┌────────────────┐  m_valid ──→  下游
              ──→ s_data    │ 单级寄存器切片  │  m_data  ──→
              ←── s_ready   └────────────────┘  ←── m_ready
```

| 信号 | 方向 | 位宽 | 含义 |
| --- | --- | --- | --- |
| `clk` | in | 1 | 单时钟域，1 cycle = 1 个 posedge |
| `rst_n` | in | 1 | 同步复位，低有效 |
| `s_valid` | in | 1 | 上游这一拍有数据 |
| `s_data` | in | 8 | 上游送来的数据 |
| `s_ready` | out | 1 | 本级这一拍能收 |
| `m_valid` | out | 1 | 本级这一拍有数据给下游 |
| `m_data` | out | 8 | 送给下游的数据 |
| `m_ready` | in | 1 | 下游这一拍能收 |

## 2. 三条约束（先当规矩用，等 R1.3 撞到问题之后再回来看为什么）

1. `m_valid` / `m_data` 只能由寄存器驱动，**不许看 `m_ready`**；
2. `s_ready` 可以组合地看 `m_ready`（方向是反的，允许）；
3. 只在 `s_valid && s_ready` 那一拍更新寄存器。

### 两个 `ready` 不恒等

最容易混的不是方向，是这一条：`s_ready` 和 `m_ready` **不是同一件事**。`m_ready` 是下游给的**输入**，`s_ready` 是本级算出来的**输出**，方向不同、归属不同。

| 我这边的状态 | 下游这一拍 | `s_ready` |
| --- | --- | --- |
| 空着 | 收不收都行 | 1 |
| 满着 | `m_ready=1` | 1 |
| 满着 | `m_ready=0` | 0 |

即 `s_ready` = "我手空着，**或者**我这一拍就能把东西交出去"。只有在"我满着"时它才等于 `m_ready`；我空着时它恒为 1，跟下游毫无关系。

差的这一点就是**这级寄存器的缓冲能力**——如果这级是纯导线（0 级缓冲），两者才恒等。

另外：`m_ready=1` 的含义是"下游**这一拍**能接"，不是"下游处理完了"。
